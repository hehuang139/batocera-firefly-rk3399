# Firefly RK3399 · Batocera 40 · TF 首启

适用板型：原版 **Firefly-RK3399** 开发板（DDR3）。ROC-RK3399-PC、ROC-RK3399-PC Plus、Core-3399J、其他 RK3399 主板的供电和内存配置不同，不能使用这份镜像。

## 准备

- 建议 16 GB 或更大 TF 卡及读卡器；烧录会清空整张卡。
- HDMI 显示器、USB 键盘或有线手柄、网线。
- 使用此板规定的独立电源及散热器，按板卡标识核对电压与极性。
- 镜像名称：`batocera40-firefly-rk3399-sd-test1.img.gz`。这是整盘 TF 镜像，不是 Rockchip `update.img`。

## 写入

1. 在电脑打开 balenaEtcher，选择 **Flash from file**，载入上述 `.img.gz`，无需自行解压。
2. **Select target** 选择 TF 卡，按名称与容量核对，然后 **Flash**。
3. 等待写入和验证完成。电脑提示格式化未知分区时取消，再安全弹出卡。
4. 开发板断电，插 TF 卡。先接 HDMI 并打开显示器，再接 USB 手柄/键盘、有线网络，最后接电源。
5. 首启等待约 5–10 分钟，系统会准备 SHARE 数据分区。进入 EmulationStation 后按提示配置手柄；可在设置中选择中文与 HDMI 音频。
6. 先用系统自带自由游戏检查画面、声音、按键与重启。自己的游戏与 BIOS 按 Batocera 相应目录添加。

## 如果进入旧系统

这表示启动链仍选中了板上 eMMC/SPI 中的旧系统，并不表示 TF 写入失败。不要反复刷卡或直接擦除 eMMC。记录旧系统名称、启动画面以及板子完整型号，再检查其启动器是否支持 TF 引导。Recovery 键不是通用的“强制从 TF 启动”开关。

本镜像的 U-Boot 自身只从 TF 加载系统；它必须先被芯片启动。Linux 设备树关闭 eMMC 控制器，因此该 TF 系统启动后不会访问原 eMMC。

## 如果黑屏

记录显示器是“无信号”、有信号黑屏、停在文字界面，还是已有 Batocera 启动画面。先用常见 1080p HDMI 显示器与直连线，去掉转换器。保持散热和独立供电。

已接有线网络时，可从路由器找 `BATOCERA` 设备。在局域网内使用 SSH 登录（Batocera 默认用户 `root`、密码 `linux`），运行：

```sh
sh /boot/collect-logs.sh
```

日志在 `/userdata/system/logs/firefly-rk3399-时间/`。如需串口，板子的调试 UART 使用 1,500,000 波特率、3.3 V TTL；不可接 RS-232 或 5 V 信号。

## 更新与 eMMC

本版是 Firefly 板级适配，不能通过在线升级覆盖为 RockPro64/OrangePi 镜像。后续使用相同 Firefly 项目的整盘更新版本。

本次交付为 TF 版；eMMC 控制器已关闭，不能把该文件当成 eMMC 专用镜像。写 eMMC 需要独立启用控制器并确认 Loader 地址映射及备份。
